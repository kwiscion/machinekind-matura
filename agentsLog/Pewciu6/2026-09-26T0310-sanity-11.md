**Coverage:**

| Area | Cases |
| --- | --- |
| Choice format | `B`, `B)`, `B.`, `b`, `odp. B`, `odp. b`, full sentence, sentence-initial "A zatem …", answer plus rejected options, `**Odpowiedź: B**`, repeated answer, English, JSON string, fenced JSON, JSON object, OpenAI `choices[]` shape, `<think>` block, ~3,600-word overlong answer |

| Records | timeout error, error object, `error: ""`, missing output, int id vs string key, whitespace id, error-then-retry, conflicting duplicate, exact duplicate, id not in keys, record without id, `finish_reason=length` (empty, and OpenAI shape) |

### Bugs found and fixed in `harness/matura_harness.py`

Before the fixes, the harness at HEAD `4bba768` (sha256 `9778b520…`) mis-graded **16 of 67** cases. After the fixes (sha256 `2e99ca18…`) it mis-grades **0 of 67**.

| # | Symptom (old harness) | Cases | Fix |
| --- | --- | --- | --- |
| 1 | Lower-case letters were never read, so `b` and `odp. b` scored 0 | c-lower, c-odp-lower | New `extract_choices`. It reads explicit answer markers first (`odp.`, `odpowiedź [to/jest]`, `answer is`), pooling letters across markers, so conflicting markers count as a hedge. A lone lower-case letter is accepted as a last resort. |
| 2 | Polish conjunction "A zatem …" was read as a second choice, so the answer counted as a hedge | c-conj-a | A sentence-initial `A` followed by a lower-case word is ignored. |
| 3 | Rejected options named in the explanation ("A jest błędna") counted as hedges | c-rejects-others | An explicit marker takes precedence over bare letters. |
| 4 | JSON answers were read raw, so letters in `explanation` counted as hedges; the decision gate saw `{"decision": …}` as unknown | c-json-str, d-json | New `grading_text` unwraps a whole-response fenced block or JSON object/array to its answer field (`answer`, `odpowiedz`, `choice`, `order`, `decision`, …). |
| 5 | `raw_response` as a JSON object without content/text, or in the OpenAI `choices[].message.content` shape, came through as empty and was graded as an **abstention** | c-json-obj, c-openai-shape | `response_text` understands the OpenAI shape and serialises other objects. |
| 6 | Reasoning models' `<think>` blocks mention every option, so the answer counted as a hedge | c-think | `<think>/<thinking>/<reasoning>` blocks are stripped before grading and in blind packets. An unterminated block counts as no answer. |
| 7 | Right entity listed next to a known distractor got full credit | e-hedge | Now routed to `needs_review` (0 automatic points, upper bound kept). |
| 8 | Accepted year plus another year got full credit | y-hedge | Now routed to `needs_review`. |
| 9 | Int ids (`900` vs `"900"`) and stray whitespace became orphans, so the key showed as `missing_output` | 900, r-ws-id | `normalize_id` (string, stripped) is used for keys, outputs, blind-pack, and audit-sample. |
| 10 | An error record followed by a successful retry of the same id was excluded as `inference_error` (first record kept) | r-retry | The successful retry supersedes the error record. It is logged as `duplicate_output` with a note. |
| 11 | Records without an id were silently mixed into the orphans | (denominator) | Separate `records_without_id` and `duplicate_records` counts in the scorecard denominator. |
| 12 | `finish_reason=length` with empty content was graded as an **abstention** | r-truncated-empty, r-truncated-openai | New `truncated_output` review flag and a scorecard `truncated_outputs` count. The item scores 0 but is not labelled abstention. This was found on the real Qwen smoke run, where reasoning used up the token budget (§4). |
| 13 | `latency_ms` was ignored | adapter sample | Converted to seconds. `model_id` and `revision` aliases were already handled. |

`blind-merge` also gained new outputs:
- `cohen_kappa`, `cohen_kappa_linear`, and `cohen_kappa_quadratic`;
- `within_1_agreement`;
- `needs_third_rater`, with `--third-rater-range`, default 3.

### Known limits kept as labelled cases, not fixed

- **e-inflected.** An inflected form that is not listed in the key's variants (`Źródłogrodu`) is a lexical miss and is graded incorrect. Key authors must list variants, or use `review_on_fail`.
- **o-enumerated.** List enumerators (`1) 3\n2) 1`) are read as order labels.
- **c-unsure.** An explicit "nie wiem" with a guess counts as abstention. This is a policy choice.
- **r-dup-conflict.** For conflicting successful duplicates, the first is kept and the other is logged.
- **Marker edge case.** "Odpowiedź a …", with the Polish conjunction right after the marker, could be read as the letter A. No fixture hits this.

## 2. Blind two-rater dry run (synthetic essays)

The packet had 12 essays from 2 sources:
- 6 template essays of deliberately varied quality (`fixtures/blind_essay_outputs_fixture.jsonl`: strong, very short, facts-only, argued, off-topic, bullet list);
- 6 essays written by the local smoke model on fictional prompts (§4).

`blind-pack` shuffled them and dropped model, backend, revision, latency, and usage. The raters were two independent Claude Haiku 4.5 subagents. Each saw only `smoke/blind_rater_instructions.md`, a synthetic 0–15 rubric (A 0–12, B 0–3 with B = 0 under 300 words, deductions 0–2), and `packet.jsonl`. Neither saw the mapping or the other rater's output.

```bash
H=agentsLog/Pewciu6/harness; S=agentsLog/Pewciu6/smoke
python3 $H/matura_harness.py blind-pack --outputs agentsLog/Pewciu6/fixtures/blind_essay_outputs_fixture.jsonl \
  --outputs $S/smoke_outputs_qwen_essays.jsonl --keys agentsLog/Pewciu6/fixtures/blind_essay_keys.jsonl --out-dir $S/blind
python3 $H/matura_harness.py blind-merge --reviewed $S/blind/reviewed_rater1.jsonl --reviewed $S/blind/reviewed_rater2.jsonl \
  --mapping $S/blind/mapping.jsonl --out $S/blind/merged.jsonl > agentsLog/Pewciu6/results/blind_dryrun_summary.json
```

| Metric (n = 12 pairs) | All 12 | Excluding 2 empty (truncated) packets, n = 10 |
| --- | --- | --- |
| Exact agreement | 8/12 = 0.667 | 6/10 = 0.600 |
| Within ±1 point | 11/12 = 0.917 | — |
| Mean range | 0.417 points | — |
| Cohen's κ (unweighted, points as categories) | 0.600 | 0.545 |
| κ linear-weighted | 0.918 | 0.897 |
| κ quadratic-weighted | 0.986 | 0.981 |
| Items with range ≥ 3 (third rater) | 0 | 0 |

- **Where the raters differed.** The largest difference was 2 points, on the facts-only template essay (5 vs 3). The other three differences were 1 point each.
- **Which κ to read.** Unweighted κ is harsh on a 16-point scale, where near-misses count as full disagreement. The weighted κ is the one to watch for essays.
- **Inflated agreement.** The two empty packets and two off-topic or very short ones are trivially 0/0. They inflate agreement, which is why the second column excludes the empty ones.

**Disagreement handling (implemented).**
- All ratings are kept in `merged.jsonl`, and the merged score is the mean.
- A range of 3 or more sets `needs_third_rater`. A third blind rater then scores the item, and the median of the three is taken. That third rater is a manual step.
- Only aggregates go to public PRs for real exam essays. The mapping stays in `private/` for real runs; here it is committed because everything is synthetic.

**Limits.**
- Both raters are the same model family. This dry run tests the mechanism, not real inter-rater reliability; real essays need at least one human or different-family rater.
- The rubric is synthetic, not the CKE scheme.

## 3. Adapter robustness (lead's core inference adapter)

**No adapter exists on origin/main yet.** At `4bba768` there is no `infer.py` and nothing adapter-shaped under `agentsLog/kwiscion/` or the lead's paths; only `docs/overnight/*` and the dispatch note exist. `CONTRACTS.md` says "A local `infer.py` prototype is not yet published".

**Assumed contract.** This follows CONTRACTS.md; `fixtures/adapter_contract_sample.jsonl` holds four synthetic records in this shape, and the ingestion test is `TestAdapterContractIngestion`.

```json
{"id": "<item id, string; int tolerated>", "backend": "transformers|llama.cpp|mlx|openai-compat",
 "model": "<repo id>", "model_revision": "<commit or weights sha256>",
 "raw_response": "<string>  OR  an OpenAI chat.completion object",
 "usage": {"prompt_tokens": 0, "completion_tokens": 0}, "latency_s": 0.0,
 "finish_reason": "stop|length (optional)", "error": null}
```

The harness also accepts these variants:

| Field | Also accepted |
| --- | --- |
| `model` | `model_id` |
| `model_revision` | `revision` |
| `raw_response` | `response`, `output`, or `text` |
| `latency_s` | `latency`, or `latency_ms` (converted) |
| `finish_reason` | inside `raw_response.choices[0]`, or as `stop_reason` |

**Handling rules.**
- A non-empty `error` excludes the item as `inference_error`.
- A retry is appended as a new record with the same id; the harness keeps the successful one.

## 4. Local smoke test of the JSONL path (NON-CANDIDATE SMOKE MODEL)

**Model.** `qwen3.6-35b-a3b-abliterated-heretic-mlx`, served by LM Studio (OpenAI-compatible) on localhost, at temperature 0. Every record is labelled `provenance: synthetic`, `provider: local-lmstudio`, `candidate: false`.
