## Design

| Step | Behaviour |
| --- | --- |
| `check` | Strict JSON (rejects a UTF-8 BOM and duplicate keys). It requires `exam_id`, a string `instructions`, and for each item a string `id`, `question`, `answer_format`, `source_text` and a finite, nonnegative `max_points`. It checks for duplicate item IDs and that the item points sum to `max_points`. Image paths must be relative and stay inside the exam folder; each file must exist with exactly this case-sensitive spelling, start with the PNG magic bytes and match the published SHA-256 (a shared image may not have conflicting hashes). The template must have exactly `exam_id`/`answers`, entries exactly `id`/`answer`, the same `exam_id` as the exam, and IDs that match the exam item IDs as sets with no duplicates. Unknown exam, item or image fields are listed in the summary (`unknown_fields_passed_to_model`). Nothing about the mock (ID, 37 items, 60 points, item 26) is hardcoded; the `--expect-*` flags are optional assertions. |
| `prepare` | One `{id, prompt, images}` record per item, in package order. The prompt contains a short header, the exam-wide `instructions`, `Zadanie <id> (maks. N pkt)` + the complete `question`, the complete `source_text`, the list of attached image paths, the `answer_format`, and a footer: "format examples show syntax only; return only the final answer in Polish". Unknown exam-level, item-level or image-level fields (for example a future `hint` or `caption`) are appended verbatim with their field name instead of being dropped; the known metadata fields `title`, `language`, `source_*`, `input_format`, `group` and `source_page` are not sent. Nothing is reordered, truncated or omitted, and `prepare` fails if any source string is not present verbatim. `images` holds real file paths relative to the JSONL file (the way `infer.py` resolves them), so `infer.py` sends the image bytes, not only filenames. U+2028, U+2029 and U+0085 are written as JSON escapes, because `infer.py` splits its input with `str.splitlines()`. A sidecar `<output>.manifest.json` records the exam/template hashes and IDs. |
| `finalize` | Reads `infer.py` output (or `scripts/normalize_outputs.py` output, which is the evaluator's format) and emits entries in template order with exactly the template IDs. `--manifest` (the prepare sidecar) is **required**, unless you explicitly pass `--no-manifest`. It must match the package's `exam_id`, item IDs, and the `exam.json` and template SHA-256. An unknown ID, a duplicate output ID, a record `exam_id` that differs from the template, a record with duplicate JSON keys, non-UTF-8 input, or a manifest mismatch is an error (exit 2, no file written). `--output` and `--report` must be distinct new paths and may never be the exam, template, image, raw-output or manifest files; this is checked before either file is written (lead P2). Reasoning never reaches the submission. Only `message.content` is used (`reasoning_content` is ignored), and for list content only parts of type `text`/`output_text` are kept. `<think>`, `<thinking>` and `<reasoning>` blocks are removed, and after an orphan closing tag (a Qwen template that opened `<think>` in the prompt) only the text after the last closing tag is kept. For Harmony output only the `final` channel is kept. An unclosed opening tag, or Harmony output without a final channel, is `malformed`. Only an explicit `finish_reason` of stop/eos/end_turn/stop_sequence counts as complete; a missing, `null` or other value (for example `content_filter`) is `incomplete` even when content is nonempty, and the next choice is tried before giving up (#45). Any non-null `error`, including `""` or `{}`, is a failure (#45). JSONL is split only on `\n`. The following become `""` plus an entry in a separate local failure report: missing records, `infer.py` errors (http/URLError/provider/incomplete), `finish_reason=length`, malformed `raw_response`, empty content, unbalanced `<think>`, text that cannot be encoded as UTF-8, and any answer over 100,000 characters (which is **not truncated**). The encoded file is checked before it is written, and every output is opened in exclusive-create mode. Exit 1 means a valid file was written but some answers are empty; unexpected crashes exit 2, so they are never confused with that case. The report records the SHA-256 of each raw output file and of the prepared input. |
| `validate` | A separate check of the final bytes: at most 1 MiB, UTF-8 without a BOM, valid JSON without duplicate keys, top level exactly `exam_id`+`answers`, each entry exactly `id`+`answer`, all values strings, every template ID exactly once (order ignored), `exam_id` equal to the template's, no lone surrogates, and each answer at most 100,000 characters counted **both** as code points and as UTF-16 units (the JS `length` view). Diagnostics are printed as JSON; the answer file is never modified. Exit 2 when invalid. |
| `fetch-mock` | The only step that uses the network. It downloads `exam-pack-1.bin` + `exam-pack-2.bin`, concatenates them in order, and checks the pinned SHA-256 of both parts, the zip, `exam.json`, the template and the README. It unzips after a path-traversal guard, checks that the zip's `exam.json`/template are byte-identical to the endpoint copies, runs `check`, and writes an aggregate manifest. It sends a descriptive User-Agent because the CDN returns 403 (Cloudflare 1010) to the default `Python-urllib` agent. |

## Limitations

- The token limit is a real risk for the essay. `infer.py` caps `max_output_tokens` at 4096 and the example Qwen config uses 512. A 300-word Polish essay needs roughly 600–1,000 tokens, and a cut answer (`finish_reason=length`) becomes `""` as the issue requires. `run` prints an advisory warning below 2048 tokens and changes nothing. The token budget stays in the config, so the lead's 1024-token baseline arm is unaffected.
- `infer.py` accepts at most 100 cases per call, so `run` splits the input into chunks of at most 100. Every chunk is dry-run validated before the first model call. The total is capped by `--max-calls-total` (default 200), and any `infer.py` exit other than 0/1 aborts. Tested with an invented 205-item package: chunks of 100 + 100 + 5, and the job is refused under the default cap. The prompt template is a plain Polish wrapper and has not been tuned; it only fixes the input contract and adds no retrieval, few-shot examples or reasoning.
- Answer post-processing is minimal: whole `<think>` blocks and surrounding whitespace are removed, and nothing else is changed (no "Odpowiedź:" prefix stripping, no reformatting to match `answer_format`). Whether an answer follows `answer_format` is left to the model and the graders.
- The organizer's format checker is not public. Its exact character counting is unknown, so `validate` checks both code points and UTF-16 units against 100,000.
- The link between raw outputs and the exam relies on the prepare manifest the operator passes. `infer.py` records carry no exam ID or input hash, so `finalize` cannot prove which prepared file produced a raw file. `run` keeps the input, raw records, manifest and answers in one new folder, which avoids the problem.
- The final exam's package layout is assumed to match the mock (the `exam.json` + `answers-template.json` + relative `images/` paths contract from the guide). If it differs, `check` fails loudly instead of guessing.
- Mock rights: the license is unknown (organizer mock of a CKE paper). Only hashes, counts, filenames and IDs are published; no text or images.
- No submission, team code or registration was touched. The upload is a later step for the lead.
