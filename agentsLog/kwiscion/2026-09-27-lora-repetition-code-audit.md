## Verified execution facts

It rejects truncation and reserved control tokens in the data. Padding/packing is absent. The real run passed these checks for all 90 records; maximum complete sequence was 2,510 tokens against a 4,096 bound. This establishes inclusion of the terminator, **not** that its probability was learned sufficiently.
- The executed training file SHA is `83153814da8251210f2b9d225dc713ad245c273bdc5d46dd1216b0e4b97178f5`. The local cleared `essay_corpus/export_v1/train_sft.jsonl` produces that exact SHA after CRLF-to-LF normalization; the separate 81-row pilot export was not used. There are 34 essay and 56 repair records, but only **34 distinct exact assistant targets**: 22 targets appear three times and 12 twice. Targets contain 409–457 whitespace-delimited words. This is intentional essay/repair reuse within training, not evidence of held-out leakage.
- `run_real_pilot.py:22–24,107–123` processes the same ordered groups of eight for three epochs: 270 presentations, 36 optimizer steps, zero synthetic training steps. The last two repair rows form a two-example update every epoch. Division by `len(group)` gives each of those examples four times the immediate loss/gradient coefficient of an example in an eight-row group; AdamW's eventual parameter influence is nonlinear and cannot be called exactly fourfold. The order is strongly task-clustered, not shuffled.
- AdamW uses constant learning rate `1e-4`, weight decay zero, with no warmup, decay schedule, or gradient clipping. All measured gradients/updates were finite and nonzero. Example-weighted training loss by epoch was 1.2401, 0.9350, 0.8884. These are training losses, not generalization measurements. LoRA r8/alpha16/dropout0.05 targets exactly 88 text q/v modules (5,193,728 trainable parameters); no vision/audio parameters were trainable.
- Published evaluation commit `057bd7e` matches the supplied current code/settings pins below. Both compared arms use the same nonthinking template, server `--reasoning off`, temperature 0, top-k 1, seed 42, and context 65,536. The server rejects a changed served-template hash. Training deliberately uses the empty thought-channel nonthinking generation prefix, consistent with that template. No thinking-mode mismatch was found. - Safe merge verifies original state keys/shapes and unchanged multimodal tensors. GGUF comparison has 667 tensors on both sides, zero tensor-metadata differences, and no reported tokenizer/template metadata differences; differing metadata are attribution/name fields. All 11 projector tensor payloads are byte-identical. The public run3 synthetic qualification stopped normally after 74 and 17 tokens. The server warning removing `</s>` from EOG is **not proof** that supervised `<turn|>` is missing: these are different tokens, and the old smoke test stopped. Exact runtime EOG membership and per-terminator probability were not measured by this audit. Numerical forward equivalence across adapter, BF16 merge and Q4 export also remains unmeasured.

## Ranked hypotheses and smallest discriminating checks

1. **Concentrated exposure and task/order bias weaken general termination or writing behavior.** Supported risk factors are only 34 unique targets, six or nine presentations per target across three epochs, repair-heavy clustered ordering, and repeatedly overweighted tail examples. Causation is unproven. If quality fails after runtime checks, the smallest single-variable training comparison is **one epoch / 12 steps**, retaining the same data, LR, targets, export and matched evaluation. Save that checkpoint explicitly; do not simultaneously sweep LR or change prompts. A later separate data-order experiment can shuffle deterministically and handle partial-batch weighting, but should not be bundled into the exposure comparison.
2. **Long greedy decoding exposes a marginal termination/repetition trajectory, possibly sensitive to runtime numerical/cache state.** No evidence establishes a cache defect. Current attempts 1–3 retain the original prompt and settings, changing only the cap (32,768 → 49,152 → 32,768); only attempt 4 adds a fallible draft. Therefore the reported short retry is not inherently a new writing strategy. The smallest next check is answer-free: after the run, reconcile chosen attempt, request hashes, cap, finish reason and token counts; establish whether synthesis occurred. Then, only in a separately authorized diagnostic, verify actual rendered prefix IDs and `<turn|>` EOG membership and measure endpoint probability on a cleared synthetic completion. No current run should be changed.
3. **Merge/quantization shifts token margins enough to magnify repetition.** Lower priority because structure, tokenizer metadata and projector checks pass and short synthetic stopping works. If the first two checks do not explain the issue, compare a tiny fixed cleared prompt set across adapter-attached BF16, merged BF16 and Q4 using identical rendered tokens. This requires a new bounded runtime authorization; it is not a reason to repeat full training now.

Recommended next action: preserve the live evaluation, collect the answer-free termination/attempt evidence when terminal, and wait for its independent quality result. There is no basis here to repair a supposedly absent EOS or launch another LR sweep.
