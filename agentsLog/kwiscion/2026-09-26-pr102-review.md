## Blocking findings

1. **[P1] Generic header removal can silently delete source material.** `scripts/Pewciu6/essay_route.py:86` removes any first paragraph containing a concision keyword and no essay keyword. It does not identify a trusted solver header. An original synthetic source paragraph saying its author described events briefly is removed before the essay builder runs. The saved hash documents the deletion but does not preserve the source in model input. Match an explicit known header, accept a separately supplied header field, or keep ambiguous prefixes unchanged. Add a source-first regression test.

2. **[P1] Published commands put raw provider/plan output into a tracked public directory.** `essay_route.py:294` and the committed pilot manifest target `agentsLog/Pewciu6/essay/pilot-v1/*.output.jsonl`; `git check-ignore` confirms these paths are not ignored. `infer.py` writes provider envelopes there, and `write.input.jsonl` later embeds the plan. Root rules require these to remain private. Generate execution outputs and plan-bearing inputs under a fresh ignored private run directory; publish only checked answer-only handoffs and safe aggregate provenance.

3. **[P1 launch gate] The 30-minute limit is declarative, not enforced.** The six calls and 7168 requested tokens are correctly calculated, but the launcher is four independent commands using ordinary `infer.py`. `max_wall_minutes: 30` has no dispatcher; six calls at the configured 420-second timeout can exceed 30 minutes. There is no shared deadline, ownership/runtime check or reservation ledger across stages. This is executable preparation plus manual stage commands, not the bounded executable pilot required for autonomous launch. Add a bounded orchestrator, or integrate these builders into an independently reviewed bounded runner before approval. Retain raw responses, failures and unsent IDs; stop without retries.

4. **[P2] Duplicate plan IDs are silently accepted and the last wins.** `essay_route.py:321` constructs a dictionary directly from plan rows. A CPU reproduction with two different completed plans for the same ID returns success and embeds only the second. Reject duplicates, unexpected IDs, malformed rows and ambiguous completion state before constructing write input. Preserve the explicitly declared missing/failed-plan fallback separately.

5. **[P2] The report undercounts errors when partial text exists.** `scripts/Pewciu6/essay_report.py:135` includes every nonempty row in its successful population, regardless of `error`. A 301-word row flagged incomplete produces `empty_or_error: 0`, `underlength: 0`, and successful min/max length 301. Count errored rows correctly and separate partial-text diagnostics from valid completed-answer summaries. Add a nonempty truncated-output regression test.
