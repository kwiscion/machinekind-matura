# Champion recovery scheduler — CPU preparation

`recovery_harness.py` is a reusable scheduling component, paired with the executable binding documented in `RECOVERY_RUNTIME.md`. No model calls qualify it. The target context of 65,536 and throughput remain unverified.

The callable `run(cases, template, out, config(60 or 120), runtime, absolute_deadline, resume=False)` preserves exact organizer IDs and complete original text/image bytes. Cases use serialized local infer content and explicit `kind: essay` metadata where applicable. The caller must validate/freeze the package and mapping before dispatch. Do not access FINAL: that access freezes all team code, prompts and settings.

The runtime interface requires `verify(context)`, `send(native_payload, timeout_seconds)` and `quiesce(deadline) -> True`. A true quiescence result must prove owned backend compute has stopped, including after a client timeout. HTTP cancellation alone is insufficient. Binding this interface to the reviewed owned service/guardian, immutable weight/runtime pins and live context checks remains required; preserve the original host service. Initial staged inventory is strict; runtime-created metadata must not be mistaken for changed model weights.

Initial attempts use thinking and 32,768 output tokens. Recovery offers a higher cap of 49,152 only with returned prompt usage proving context fit, then thinking off, then full original sources plus bounded explicitly fallible notes. Breadth-first scheduling gives every initial item its remaining-time share before recovery, reserves ten minutes for recovery/finalization, and recalculates after each measured call. Four attempts are available per unresolved item; successful recovery ends that item's ladder. Fatal integrity/runtime failures or a hard deadline record unfulfilled attempts. No claim is made that all four attempts can fit before measured throughput exists.

Durable request reservations precede sends. Resume consumes orphan reservations without replaying the same attempt. Complete finals survive failed repairs; otherwise the longest validated length partial is submitted as incomplete, never successful recovery. Final fallback is exactly `Tadeusz Kościuszko`, explicitly marked placeholder. Exact UTF-8 file limits are enforced; when necessary, a codepoint-safe bounded partial replaces an oversized answer and the original remains in private evidence. Planning hooks are excluded: only frozen `output_kind=final_answer` suffix hooks are supported until an explicit plan-to-writer protocol exists.
